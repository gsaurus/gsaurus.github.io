Behaviour Modes¶

Behaviour fields store the same objectMode values used by the Unity runtime move tables. For players and enemies, the mode value is controller array index * 2. For items, the mode value is (controller array index + 1) * 2, because item mode 0x02 selects the first item controller.

The editor behaviour picker is generated from PlayersMoves.cs, EnemiesMoves.cs, and ItemsMoves.cs. For animation Behaviour, the reference picker is limited by the edited character's Classic base: playable characters can reference only the four classic playable characters, enemies can reference classic enemies, and items can reference classic items. The behaviour list then comes from the selected reference entity.

Animation event override¶

If an animation defines any logic events, those events override the default behaviour for that animation. In game, a local animation with events applies those events and the local default physics step, then skips the referenced classic move controller. This prevents original mode side effects such as forced mode changes, timers, hard-coded spawns, damage transitions, or special-case movement from leaking into custom event-based animations.

Scripts can still provide custom logic. Animation Behaviour and fallback classic behaviour only run for animations without events.
